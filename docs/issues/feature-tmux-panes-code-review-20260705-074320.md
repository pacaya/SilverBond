### H1. Tmux control nodes (`send`/`wait`/`capture`/`kill`) can target arbitrary panes without the unlock gate or run-ownership check (FIXED)
> **Fix:** Added a run-scoped tmux ownership registry; resolve_pane_target now rejects any pane not owned by the current run across all four control executors; deliberately deferred the privileged-unlock escape hatch (no per-run unlock flag exists yet), so the allowlist rejects unconditionally.
**Severity:** HIGH — privilege-gate bypass: keystroke injection (arbitrary command execution), cross-run output exfiltration, and pane/session destruction against any pane owned by the server's OS user. **Description:** `authorize_and_prepare_run_security` (`src/api.rs:649-677`) gates the unlock requirement only on `workflow_launches_processes` (which sums `node_launches_process`, `src/api.rs:724-732` — matching only `Task`/`Decide`/`Spawn`/`RunAgent`) or a `run_as` prefix, so a workflow built solely from `send`/`wait`/`capture`/`kill` nodes is never "privileged" and skips the unlock path. **Fix:** Enforce a run-owned pane allowlist inside `resolve_pane_target`. Because all four control executors (`execute_send`/`execute_wait`/`execute_capture`/`execute_kill`) funnel through this one function, the single chokepoint covers keystroke send, wait, capture, and kill symmetrically.

### H4. `wait until` / `wait ready` nodes report SUCCESS without ever matching the marker (FIXED)
> **Fix:** wait_for_mode now returns success alongside the outcome, keyed on the configured terminator (Until⇒UntilMatched, Ready+marker⇒ReadyMatched, markerless Ready/Idle⇒!TimedOut); all four wait call sites consume it; 3 regression tests added.
**Severity:** HIGH — a user-authored control-flow gate (`until`/`ready` + `reject` branches) silently passes: a `wait until` never requires its marker, and the sequence-runner readiness site falsely asserts "ready" before the agent is ready. Bounded to workflows that actually use `mode: until`/`ready` (default `Idle` is unaffected) and require the pane to go static, but no test covers idle-as-success for wait nodes.
**Files:** `src/tmux_exec.rs:652` (`execute_wait`), `src/tmux_exec.rs:1194`/`:1203` + `:1229`/`:1230` + `:1268`/`:1269` (`run_agent_sequence` — 3 sites, the readiness one omitted by the original finding), `src/tmux_exec.rs:2133` (`wait_for_mode`), `src/tmux_exec.rs:1670-1675` (`is_interactive_completion_reason`, the correct contract), `tmux-tools/core/src/idle.rs:162-172` (`wait_for_idle`), `src/model.rs:427-449` (`WaitMode`/`WaitConfig`)
**Description:** Wait-node success is computed as `reason != IdleReason::TimedOut` at four sites — `execute_wait` (`src/tmux_exec.rs:652`) and three in `run_agent_sequence` (`:1203` readiness, `:1230` response, `:1269` idle). `wait_for_mode` (`:2133`) builds the `until`/`ready` regex per mode but returns the raw `IdleOutcome` without evaluating mode-vs-reason; `wait_for_idle` (`tmux-tools/core/src/idle.rs:162-172`) returns `IdleReason::Idle` whenever the pane is static for `idle_seconds` with the marker unmatched (`UntilMatched`/`ReadyMatched` fire only on an actual match). So a node `mode: until, marker: "TESTS PASSED"` returns success/exit 0 when the agent finishes printing `TESTS FAILED` and idles — the `reject` branch never fires — and the readiness site falsely asserts "ready" and sends its prompt early. `is_interactive_completion_reason` (`:1670-1675`) already accepts only `ReadyMatched`/`UntilMatched`, so these four sites are the outliers — the residue of a one-sided 2026-06-08 hardening of the interactive path.
**Fix:** Move the success verdict into `wait_for_mode` (return it alongside the `IdleOutcome` — the fn already owns `cfg.mode` and knows whether it built an `until`/`ready` regex) and have all four call sites consume it. Key the verdict on the configured terminator, not the mode label:
- `WaitMode::Until` ⇒ success requires `reason == UntilMatched` (marker is mandatory in Until).
- `WaitMode::Ready` with a configured ready marker ⇒ success requires `reason == ReadyMatched`.
- `WaitMode::Ready` with no marker / `WaitMode::Idle` ⇒ accept `Idle` (`success = reason != TimedOut`) — preserves the marker-less-`Ready` carve-out so readiness waits with no `ready_regex` don't regress to always-fail.
- Carry the raw `reason` in the return so callers can distinguish "marker never matched" from a true timeout for messaging.

This covers `execute_wait` and all three `run_agent_sequence` sites (including the `:1194`/`:1203` readiness gate the original finding omitted), and any future caller inherits the rule.
