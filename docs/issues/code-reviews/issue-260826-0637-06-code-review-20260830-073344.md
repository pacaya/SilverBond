### M1. Edge `condition` applicability and evaluation gate are both misstated (FIXED)

> **Fix:** Rewrote the `condition` row: branch-only + non-`decide` applicability (`src/runtime.rs:6527-6539`), silent ignore on the other outcomes with validation not flagging it (`src/model.rs:1896-1914`), the decide early-return (`src/runtime.rs:6383-6443`), and the real gate as `result.parsed_output` presence (`:6529`) with the system-output kinds named. Both reviewers re-resolved every new citation.

**Severity:** MEDIUM · **File:** `docs/workflow-schema.md:1278-1280` · **Source:** Both

Merged finding — Codex's CODEX-1 subsumes Claude's CLAUDE-1, CLAUDE-2 and CLAUDE-3, which split the
same defect three ways. Two independent errors in the `condition` row:

1. **Applicability.** `edge.condition` is read at exactly one place in the engine —
   `src/runtime.rs:6533`, inside the `if !branch_edges.is_empty()` arm at `:6527` over the
   `WorkflowEdgeOutcome::Branch` filter at `:6369-6373`. A `condition` on a `success`, `reject`,
   `loop_continue` or `loop_exit` edge deserializes, round-trips, and is never evaluated; validation
   does not flag it either (`src/model.rs:1896-1914` warns only for branch edges). Additionally the
   `decide` arm (`src/runtime.rs:6383-6443`) returns on every path — matched edge or fall-through —
   before reaching condition evaluation, so `condition` on a decide node's branch edges is dead too.
2. **Gate.** The doc says evaluation happens "only when `responseFormat` is `json`". The real gate is
   `result.parsed_output.is_some()` (`src/runtime.rs:6529`). `parse_structured_output`
   (`:7208-7226`) populates it from agent text only under `responseFormat: json`, but several kinds
   populate it directly regardless: `capture` (`src/tmux_exec.rs:893-907`), `parallel_batch`
   (`src/runtime.rs:5334`), `decide`, `split`, `collector`. Since a non-json `responseFormat` is only
   a warning, those nodes do evaluate conditions — contradicting the table.

**Fix:** State that only `branch`-outcome edges on non-`decide` nodes consult `condition`, that other
outcomes and decide branches ignore it silently and validation does not flag that, and that the gate
is the presence of parsed output — `responseFormat: json` being what produces it for prompt-driven
nodes, while system-output kinds produce one unconditionally.

**Cluster — one defect, not three.** Round 1's fix for M2 rewrote `:1450-1468`, and re-verification
surfaced two further findings inside that same rewritten region: Codex's NEW-1 (MEDIUM, contradictory
miss behaviour) and Claude's CLAUDE-14 (LOW, invented error path). Per the same-site escalation rule,
the patch and the findings are the same prose disagreeing with itself, so they are recorded here as
one defect and round 2 switches mode: **redesign the region, do not patch the sentences.**

**What landed in round 1 and is correct** — keep it: unconstrained node ids
(`src/model.rs:1598-1606`), the full precedence order, which both reviewers checked line by line
against `resolve_template_vars` and found to match exactly, and the `[^.}]+` capture consequence.

**The three surviving defects, all verified by the orchestrator against source:**

1. **Self-contradiction on the uncapturable dot-path id.** `:1457-1458` concludes the token "survives
   verbatim rather than resolving or becoming empty"; `:1462-1463` then says the dot-path forms
   substitute the empty string "(and when the node id cannot be captured by the regex)". The document
   asserts both outcomes for one input. `Regex::replace_all` cannot replace text it never matched, so
   verbatim is correct and the parenthetical is false.
2. **Overstated `var:name` shadowing.** `:1454-1456` says a completed node whose id is `var:name`
   consumes that token first. The variable loop runs at `src/runtime.rs:7065-7067`, *before* the
   bare-node loop at `:7068-7071`, so the node wins only when the variable binding is absent.
   (`previous_output` and `context:name` shadowing is stated correctly — those loops do run later.)
3. **Invented error path.** `:1461` opens "Nothing errors on a miss unless an earlier substitution
   form already consumed the token". `fn resolve_template_vars(...) -> String`
   (`src/runtime.rs:7063`) returns `String`, not `Result`; every substitution is an infallible
   `str::replace` or a `replace_all` closure ending in `.unwrap_or_default()`. Nothing errors under
   any condition — shadowing yields a wrong substitution, never an error. The clause also weakens
   `CONTEXT.md`'s flat "nothing errors on a miss", which the Agent Brief requires this section to
   state.

**The mechanism to remove.** Two orthogonal axes are interleaved in one prose block: (A) *which form,
if any, matches a token* — precedence, shadowing, regex-capture failure; and (B) *given a form
matched, what it does when the binding is missing*. Every defect above is a qualifier from one axis
landing on a claim from the other. Point-patching the sentences will keep reproducing that, which is
exactly why round 1's fix created two new findings while closing none.

**Fix — restructure into the two axes, stated separately:**

- **Axis A — which form matches.** Precedence order; an earlier match shadows later forms, with the
  `var:name` case correctly qualified as "only when no variable of that name is bound"; a dot-path
  token whose node id contains `.` matches neither regex. Outcome for this axis is always: *the token
  is left in the prompt verbatim.*
- **Axis B — miss behaviour, given a form matched.** Open with the unconditional absolute "Nothing
  errors on a miss." Then the three groups as they already stand: two dot-path forms → empty string
  when node or field is absent; four name-keyed forms → verbatim; four remaining forms → always
  substitute, empty string when there is no value.

**Checkable properties the redesign must satisfy** (a fix that leaves the mechanism standing is
rejected on judging even if the named sentences are gone):

1. The region contains exactly one statement about the uncapturable dot-path id, and it says
   verbatim. No sentence anywhere in the region attaches "empty string" to that case.
2. "Nothing errors" appears with no `unless`, no conditional, and no exception clause attached.
3. Every shadowing claim that names `var:` is qualified by the absence of a variable binding.
4. Axis A facts and Axis B facts are not interleaved: no Axis-A qualifier appears inside an Axis-B
   sentence, and vice versa.
