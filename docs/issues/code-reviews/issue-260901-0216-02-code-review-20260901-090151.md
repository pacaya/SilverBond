### L4. JS `.trim()` and Rust `str::trim()` disagree on U+0085, leaving the fix a hole (FIXED)
> **Fix:** Replaced `.trim()` with a `\p{White_Space}` boundary replacement. Closed in both directions, not just the reported one — that property and Rust `char::is_whitespace` are the same 25 code points, so U+0085 is now stripped and U+FEFF is now correctly left alone.

**Fix:** Trim on the same Unicode `White_Space` set the Rust validator uses (a Unicode property-escape boundary replacement rather than the built-in `.trim()`), and add a seam test with an independent U+0085-padded fixture.

### M5. The loosened e2e predicate can capture the pre-edit validation request and flake (FIXED)
> **Fix:** Predicate is now `branchEdge !== undefined && branchEdge.label !== null`, which discriminates edit-ness without encoding the value under test. Claude re-ran the exact 900ms-delay experiment that broke round 2 and the spec now passes, while the diagnostics survive: removing store normalization fails it with `Expected: "yes" Received: "yes "` rather than a timeout. Codex confirmed statically that the fixture starts `branch_yes` with a null label, so the import request cannot satisfy the wait.

**Severity:** MEDIUM · **File:** `ui/e2e/branch-edge-label-trim.spec.ts:31-38` · **Source:** Both (CLAUDE NEW-5, CODEX-7) · **Round:** raised by fix-round-2 re-verification

L12's fix moved the expected value out of the `waitForResponse` predicate, which was right — but it left the predicate accepting *any* validation request carrying the `branch_yes` edge. Validation is debounced 500ms and the timer restarts on every workflow change (`ui/src/app/AppShell.svelte:89-100`). Loading the fixture starts a timer; `fill` restarts it. The spec passes today only because the machine gets from file-load to `fill` inside 500ms, cancelling the load-time request. On a slower or colder box that window stretches, the load-time validation fires after the waiter is registered, the predicate accepts it, and the assertion sees the pre-edit `null` label.

Claude reproduced this deterministically by inserting `await page.waitForTimeout(900)` before the fill: `Expected: "yes" Received: null`. The damaging part is that this failure is indistinguishable from a genuine normalization regression, so it would send someone hunting a bug that does not exist. Round 1's strict predicate was immune; L12 removed the immunity along with the opaque timeout.

**Fix:** Make the predicate discriminate *edit-ness* without encoding the value under test — `return edge !== undefined && edge.label !== null`. Pre-edit requests carry `null` and are skipped, while a regressed normalizer still yields `"yes "`, which the predicate accepts and the assertion then prints as a real diff. **Do not** use the alternative of requiring `label === "yes"`: that re-encodes the expected value in the predicate and restores exactly the opaque-timeout failure mode L12 was filed to remove.

### M6. An edit that normalizes to the stored value leaves a stale draft visible after undo (deferred)

**Severity:** MEDIUM · **File:** `ui/src/features/editor/EdgeInspector.svelte:48` · **Source:** Codex (CODEX-8) · **Round:** raised by fix-round-3 re-verification

M4's reconciliation decides draft validity by comparing the *normalized* draft against the stored label.
