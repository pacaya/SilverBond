### M1. Collapse-to-undefined path is never exercised from a populated toolToggles (FIXED)
> **Fix:** Added `"collapses stored toolToggles to undefined when selecting inherit"` (`AgentConfigFields.test.ts:80-85`) starting from a populated sole-key `{ webSearch: false }` base, driving the select to `""` and asserting the spy's emitted value is `undefined`. Proven red by both reviewers independently — bypassing `mergeConfig`'s `delete` branch yields `{ webSearch: undefined }` and the test fails; `mergeConfig.ts` confirmed byte-identical to HEAD afterwards.

**Severity:** MEDIUM · **File:** `ui/src/features/editor/AgentConfigFields.test.ts:62-73` · **Source:** Both (CLAUDE-1 + CODEX-1, mutually AGREEd)

The "emits on, off, and inherit" test calls `setup()` with `values = {}`, and the spy `update` never feeds
state back into the component (no rerender), so `values.toolToggles` stays `undefined` across all three
`fireEvent`s. The inherit assertion therefore passes because the merge *base* was already empty —
`mergeConfig` spreads `{}` and returns `{}` — not because a stored `webSearch` key was deleted and the
resulting object collapsed.

The realistic and most common user path is untested at the named seam: stored `{ webSearch: false }` (or
`{ webSearch: true }`) with no siblings, user selects inherit, component must emit `undefined`. A
regression dropping the `delete` branch (writing `next[field] = value` unconditionally) would emit
`{ webSearch: undefined }` — `Object.keys(...).length === 1`, so `update` receives an object instead of
`undefined`, the caller never prunes, and all three existing assertions still pass. Acceptance criterion
3 is satisfied only apparently.

**Fix:** Add a case starting from `setup({ toolToggles: { webSearch: false } })`, drive the select to
`""`, and assert `expect(update).toHaveBeenLastCalledWith("toolToggles", undefined)`. Keep that
transition independent of the on/off cases.

### M2. Tautological distinct-state assertion that exercises no code (FIXED)
> **Fix:** Replaced the literal-vs-literal comparison with captured observed values `inheritValue`/`onValue`/`offValue` (`AgentConfigFields.test.ts:49/54/59`) and pairwise inequality assertions over those observations (`:62-64`), keeping the three per-state expectations. **Severity:** MEDIUM · **File:** `ui/src/features/editor/AgentConfigFields.test.ts:59` · **Source:** Both (CLAUDE-2 + CODEX-2, mutually AGREEd)

neither the component nor any captured value. It appears to exist to discharge acceptance criterion 4's
"the absent case and the `false` case must not assert equal" requirement, but that criterion is already
met by the three distinct rendered-value expectations at lines 49, 53 and 57. As written it is dead
weight that gives a false impression of coverage, and it violates the inner loop's tautological-test
rule.

Severity taken as MEDIUM (Claude's grade) over Codex's LOW: this is the assertion that nominally
discharges an acceptance criterion, so its emptiness is a spec-axis gap rather than a style nit.

**Fix:** Capture the three rendered values into variables and assert inequality over the *observed*
values (`expect(inherit).not.toBe(off)`), or delete the line since the three distinct expectations
already establish distinctness.

### L1. Section-predicate test has a single positive assertion and no negative control (FIXED)

**Severity:** LOW · **File:** `ui/src/lib/utils/sectionUtils.test.ts:14-18` · **Source:** Claude (Codex DISAGREE — adjudicated: keep)

**Fix:** Add negative controls in the same suite: `taskNode({})` → false, `taskNode({ toolToggles: {} })`

### L2. Presence test now counts an explicit null as configured (dismissed: not reachable frontend state)

**Severity:** LOW · **File:** `ui/src/lib/utils/sectionUtils.ts:43` · **Source:** Claude (Codex DISAGREE — adjudicated: dismissed)

Claimed that `cfg.toolToggles?.webSearch !== undefined` admits `null` (falsy but not `undefined`), so a
document carrying `toolToggles: { webSearch: null }` would auto-open the agent-tuning section while the
control renders it as "agent default".

**Adjudication — dismissed.** Verified against both type systems: the frontend declares
`webSearch?: boolean` (`ui/src/lib/types/workflow.ts:45-47`), and the Rust struct declares
`Option<bool>` with `#[serde(default, skip_serializing_if = "Option::is_none")]`
(`src/driver.rs:516-519`) — an incoming JSON `null` deserializes to `None` and `None` is omitted on
serialization, never emitted as `null`. So `null` cannot survive a backend round trip into the editor,
and it is outside the declared frontend domain. The reporting reviewer graded its own confidence at 30.
No code change.
