#### Issue M17: Non-atomic workflow writes plus fail-fast listing
**Severity:** MEDIUM
**File(s):** `src/storage.rs:880-887` (`save`), `:841-861` (`list`), `:844` (extension filter), `:882` (`ensure_dir`), `:889-894` (`delete`), `:919-947` (`TemplateStore::list` convention), `:1247` (happy-path test), `:1267` (template skip test); `src/api.rs:494-495` (`GET /api/workflows`), `:2430-2435` (error mapping) *(pre-existing, untouched by this branch)*
**Description:** Severity rationale: MEDIUM — real data loss with an all-or-nothing blast radius on the list endpoint and no recovery path, offset by a millisecond-scale crash window on a single-user local app writing small JSON.

`WorkflowStore::save` writes with `tokio::fs::write` — `O_TRUNC` with no fsync — so a crash mid-save leaves an empty or half-written `.json` (`src/storage.rs:880-887`). `WorkflowStore::list` then propagates the first read/parse/normalize error through three bare `?` at `:849-851`, so a single damaged file makes `GET /api/workflows` return HTTP 500 (`src/api.rs:494-495`, `:2430-2435`) and the sidebar shows *no* workflows rather than just omitting the broken one. There is no backup, no `.bak`, and no in-app repair: the only remedy is `DELETE /api/workflows/:name` for a name the UI can no longer display, or hand-editing the filesystem. `TemplateStore::list` (`:919-947`) already establishes the warn-and-skip convention in the same file with a regression test at `:1267`; `WorkflowStore` has none.

*Correction to the original write-up:* `hydrate_saved_subflows` does **not** call `list` — it calls `get(&name)` per referenced subflow (`src/api.rs:581`), so a corrupt file breaks hydration only for workflows that reference that specific subflow by name. The "fails wholesale" claim holds for the list endpoint only.
**Recommended Fix:** Make the write durable and atomic, and make the read resilient, mirroring the `TemplateStore` convention already in this file.
- In `save`, serialize to `<dir>/<safe>.json.tmp`, `sync_all()` the file handle, then `tokio::fs::rename` over `<safe>.json`. `ensure_dir` at `:882` already guarantees the directory exists and the temp file lands in that same directory, so the rename is a same-filesystem atomic replace.
- Keep the `.json.tmp` suffix specifically: `list` filters on `ends_with(".json")` (`:844`), so an orphaned temp file is invisible to the scan. A `.tmp.json` suffix would *not* be — do not reorder it.
- Convert `list`'s three `?` at `:849-851` into `match` / `tracing::warn!` / `continue`, mirroring `:919-947`, so one bad file is skipped rather than failing the endpoint.
- Have the `list` scan unlink stale `*.json.tmp` entries it encounters, so a crash between write and rename cannot accumulate debris. Accept the mild layering smell of a read path performing cleanup.
- `save` is the only writer needing this treatment — `delete` (`:889-894`) is `remove_file`, which is already atomic.
- Add a `lists_workflows_and_skips_invalid_files` regression parallel to `:1267`; the existing `stores_workflow_files` (`:1247`) is a happy-path round-trip only.
- Optional follow-on, not required by this fix: surface skipped filenames to the UI so the user can identify and repair the damaged file rather than silently losing it from the list.

#### Issue L1: `create_dir_all` syscall on every database operation
**Severity:** LOW
**File(s):** `src/storage.rs:976-989` (`with_connection`), `:983-986` (the `ensure_dir` block), `:985`, `:987` (pool checkout), `:99` (`with_init(configure_connection)`), `:119`–`:820` (19 non-test call sites), `:415` (`append_event`); `src/app.rs:34` (`AppPaths::from_root`), `:284-289`, `:296-297`; `src/runtime.rs:6571-6572` (`emit_event`); `src/api.rs:2498-2509`, `:4224-4234` (no-init test constructors)
**Description:** Severity rationale: LOW (borderline dismiss) — real, newly-introduced redundancy, but ~2 syscalls (~1–2 µs) on a path running at single-digit ops/sec and already guaranteed at `src/app.rs:284`; worth doing only as cleanup bundled with the `path`-parameter removal.

`with_connection` calls `ensure_dir(parent)` at `src/storage.rs:985` on every invocation, before `connection.get()` at `:987`, across 19 non-test call sites including `append_event` (`:415`). In production this is pure duplication — `Application::boot` already runs `ensure_dir` on the database parent at `src/app.rs:284-289`, before `Database::new` (`:296`) and `db.init()` (`:297`). Introduced by commit `dac8d59` as collateral of the `Arc<Mutex<Option<Connection>>>` → r2d2 `Pool` migration, which hoisted the call out of the `if guard.is_none()` first-open branch; there is no runtime path that removes the directory, so the per-call repetition buys nothing.

*Corrections to the original write-up:* the real cost is ~1–2 µs (one `mkdir` returning `EEXIST` plus one `is_dir` stat — not per path component) against a `spawn_blocking` + pool checkout + WAL write, at a realistic peak of single-digit DB ops/sec, so "hot path" overstates it. The per-call `ensure_dir` is **not** load-bearing: `remove_dir_all` appears only at `src/runtime.rs:11831`/`:11856` against agent temp dirs, and the DB path is fixed per-root (`src/app.rs:34`), not per-run. The two test states that build a `Database` without `ensure_dir` or `init` (`src/api.rs:2498-2509`, `:4224-4234`) drive pane-stream tests that never touch the DB.

*Prior history:* not a regression of a deliberate fix. `20260620-092605` M9 introduced `with_connection` with `ensure_dir` deliberately scoped to first-open only, so relocating it restores that intent rather than reverting a prior decision.
**Recommended Fix:** Move the invariant to the point where it is actually true — connection open — rather than to a lifecycle method that callers can bypass.
- Introduce a thin `ManageConnection` wrapper around `SqliteConnectionManager` whose `connect()` runs `ensure_dir(parent)` and then delegates, replacing the `with_init(configure_connection)` wiring at `src/storage.rs:99`. The pool (`min_idle(0)`, `max_size(8)`) is the only thing that opens connections, so the directory is guaranteed for every connection at most 8 times per process instead of once per call.
- Delete the `ensure_dir` block at `:983-986` and drop the now-unused `path: &Path` parameter from `with_connection`, updating all 28 call sites (19 non-test at `:119`–`:820`, ~9 in tests). `path` is used for nothing else in the function.
- Prefer this over hoisting into `Database::init`: a newly-minted connection still recreates the directory if it is removed externally, and the guarantee does not depend on a caller remembering to call `init` — which the constructors at `src/api.rs:2498-2509` and `:4224-4234` already skip.
- Accept the ~20-line wrapper type as the cost of stating the invariant where it holds.
