#### Issue L3: `--exclude-dir` misuse in the new CI guard script
**Severity:** LOW
**File(s):** `scripts/check-canonical-v4-docs.sh:11-15` (rg branch), `:17-21` (grep fallback), `:18-19` (the bad globs); `.github/workflows/canonical-v4-docs.yml:9`, `:16`; tripping content at `docs/issues/feature-tmux-panes-code-review-20260610.md:121-122` and `docs/issues/feature-tmux-panes-code-review-20260705-074320.md:593`, `:594`, `:611`
**Description:** Severity rationale: MEDIUM — *raised from LOW*: the branch's own new CI gate is failing on every push right now, for a reason unrelated to the code it guards. ID retained as `L3` for stability.

`scripts/check-canonical-v4-docs.sh:17-21` passes path-shaped globs to `grep --exclude-dir`, which matches directory **basenames** only, so `docs/issues` and `docs/tasks` are never excluded. Verified empirically on the same tree with both BSD grep 2.6.0 and a from-source GNU grep 3.11: `--exclude-dir=docs/issues` prints matches (exit 0), `--exclude-dir=issues` finds none (exit 1) — BSD grep does support the flag and treats a path-shaped glob identically. The `rg` branch at `:11-15` is correct, since `--glob '!docs/issues/**'` is path-anchored, so the two branches are not equivalent implementations. `.github/workflows/canonical-v4-docs.yml:9`, `:16` runs the script on `ubuntu-latest` with no install step, and the Ubuntu 24.04 runner image ships no ripgrep, so CI always takes the broken fallback and the job is **red on every push and PR today** — the review documents themselves contain `canonical v3` / `v3-only workflow schema` and trip the guard.

*Corrections to the original write-up:* "fails spuriously on any machine without ripgrep" understates it — the fallback is the default CI path, not an edge case. The `node_modules`/`target` half is overstated for CI: on a fresh checkout neither directory exists, and `-I` suppresses `.git` binary matches. Locally, though, the multi-GB `target/` makes the fallback pathologically slow.

*Provenance:* added in `ab8eee3` as the fix for L12 of `docs/issues/feature-tmux-panes-code-review-20260705-074320.md:591`, then widened in `3790df1`.
**Recommended Fix:** Collapse the rg/grep fork into one portable path built on git pathspecs, removing the divergent-implementation root cause rather than one instance of it.
- Replace both branches (`:11-21`) with a single pipeline: `git ls-files -z -- ':!docs/issues/**' ':!docs/tasks/**' ':!scripts/check-canonical-v4-docs.sh' | xargs -0 -r grep -InE "$PATTERN"`.
- Git pathspecs are genuinely path-scoped and behave identically under BSD and GNU userlands, so the exclusion works everywhere without a ripgrep dependency or an apt install step in the workflow.
- Tracked-file enumeration inherently skips `node_modules`, `target`, and `.git`, which also removes the local slowness.
- Keep `xargs -r` so an empty file list cannot leave `grep` reading stdin and hanging the job.
- The guard's pattern is plain ERE, so nothing is lost by dropping `--pcre2` along with the rg branch.
- Scanning only tracked files is correct here: the guard exists to police committed docs, and `public/` is tracked.
- Verify by running the script on a clean `git archive HEAD` checkout with ripgrep absent from `PATH`; it must exit 0.
