#### Issue M6: `extraArgs` are appended after access-mode flags, defeating the documented access ceiling
**Severity:** MEDIUM
**File(s):** `src/tmux_exec.rs:2141-2183` (`build_agent_command`, `:2146`, `:2158-2162`, `:2161`, `:2171`, `:2178`), test `:3332-3335`; `src/driver.rs:687-688`, `:823-848`; `src/model.rs:419`, `:520`; `ui/src/features/editor/InspectorPanel.svelte:840`, `:1320`
**Description:** Severity rationale: MEDIUM (lower band) — *lowered*: author-only configuration footgun with no third-party injection path and no shipped template exercising it; still a silent, real downgrade of a declared access ceiling.

`build_agent_command` assembles argv as `once(binary).chain(session_args.args).chain(extra_args.iter().cloned())` (`src/tmux_exec.rs:2158-2162`), appending `cfg.extra_args` verbatim after the driver's session args on all three branches (`:2161`, `:2171`, `:2178`) with no filtering anywhere. Access args are emitted inside the driver — claude at `src/driver.rs:688`, codex `--sandbox <mode> -a <policy>` / `--full-auto` at `:823-848`. An author who declares `accessMode: read_only` and also types a skip-permissions entry or `--sandbox danger-full-access` into the free-text `extraArgs` textarea (`InspectorPanel.svelte:840`, `:1320`) gets the later flag: claude-code's skip-permissions flag is a boolean that simply turns on, and codex is clap v4 `ArgAction::Set`, so a second `--sandbox`/`-a` overwrites rather than erroring. `extra_args` flows verbatim from workflow JSON (`src/model.rs:419`, `:520`) through `src/tmux_exec.rs:1006`, `:1246` to `:2146` with no validation at any point.

*Correction to the original write-up:* the comment cited as the broken invariant — `// Access mode is the ceiling; explicit tool lists only refine it.` at `src/driver.rs:687-688` — sits **inside** `ClaudeDriver::build_session_args` and governs `allowed_tools`/`disallowed_tools` ordering relative to access args. It says nothing about `extra_args` and is not false as written; the review reads it wider than its scope. Mitigating: `extra_args` has **no variable interpolation** anywhere in `src/model.rs`/`src/runtime.rs`/`src/tmux_exec.rs` — it is verbatim author JSON with no third-party injection channel — and no shipped template uses `extraArgs`. One combination may fail closed rather than escalate: `--full-auto` (emitted for `Execute`) plausibly carries a clap `conflicts_with` against `--sandbox`, so that pairing fails to launch; the `read_only` → unrestricted path, which is the one that matters, does escalate.

*Prior history — "extra args last" is a deliberate decision, made twice:* `docs/issues/code-review-20260608_part_2_of_4.md:73` (F5, HIGH, FIXED) specifies exactly this order, so that "`build_session_args` [is] the single source of all dynamic config/safety flags"; the test at `src/tmux_exec.rs:3332-3335` ("driver-rendered session args should precede caller extra args") encodes it, added in `05eb37c` alongside the `driver.rs:687` comment. `docs/issues/feature-tmux-panes-code-review-20260620-092605.md:176` then adjudicated: "`command`/`extra_args` stay free-form (intended); their blast radius is now bounded by the enforced identity." Reordering argv would reverse F5; the chosen fix deliberately does not.
**Recommended Fix:** Reject access-affecting flags in `extra_args` at workflow-validation time, preserving the existing argv ordering.
- Add a validator in `src/model.rs` alongside the existing `validate_run_as_config`, applied to both `SpawnConfig.extra_args` (`:419`) and `RunAgentConfig.extra_args` (`:520`).
- Implement it as **normalize-then-match**, not naive string equality: split each entry on `=` to catch `--flag=value`, prefix-match against a per-agent flag set to catch clap's unambiguous long-flag abbreviations (e.g. `--sand=…`), and reject codex `-c` config-override keys touching `sandbox`/`approval` — an equivalent escalation channel the original fix list omits entirely.
- Cover at minimum: the skip-permissions flag, `--permission-mode`, `--allowedTools`, `--disallowedTools`, `--sandbox`, `-a`, `--ask-for-approval`, `--full-auto`, and the bypass-approvals-and-sandbox variant.
- Surface the rejection at authoring time in the UI so the author sees why the workflow is invalid, rather than discovering it at spawn.
- Do **not** reorder argv to place access args after `extra_args`: that reverses F5's finalized "single source of all safety flags" design, breaks the `:3332-3335` test contract, leaves contradictory duplicate flags in argv, and would break any `extra_args` that legitimately ends in a positional or `--`.
- Add regressions for each blocked form (`--flag value`, `--flag=value`, abbreviated, and `-c sandbox_mode=…`), plus a positive case confirming benign flags like `--model` still pass.

#### Issue M11: `spawn` nodes select an arbitrary access profile with no ceiling check
**Severity:** MEDIUM
**File(s):** `src/tmux_exec.rs:656-694` (`execute_spawn`, `:678` dropped config), `:286`, `:317-319` (config in scope one frame up), `:2166-2182` (`build_agent_command` registry branch), `:2172-2179` (swallowed profile error), `:2182`→`:2122-2123` (`KEY_ACCESS` stamp), `:2069-2076` (command-override bypass); `src/driver.rs:281-322` (`resolve_registry_access_profile`), `:295-305` (widening guard), `:268-279` (`agent_access_profile_names`); `src/model.rs:411-425` (`SpawnConfig.access`), `:1486-1512` (validation that omits it); `ui/src/features/editor/InspectorPanel.svelte:1301-1307` (spawn Access field), `:782-788` (RunAgent twin); `src/agents/mod.rs:216-218`, `:222-240`
**Description:** Severity rationale: MEDIUM (lower band) — an inheritance/validation defect, not an authorization bypass: `access` is author-controlled JSON with no third-party injection channel and omission fails *safe* for three of four builtins; held at MEDIUM because a user-facing safety control ("inherit") does not do what it says and one path stamps a pane with an access profile that was never applied.

`execute_spawn` discards the run's resolved `AgentConfig` at `src/tmux_exec.rs:678` even though it is in scope one frame up (`:286`, dispatch `:317-319`), forcing `build_agent_command` down the registry branch at `:2166-2182`. That branch calls `registry.launch_argv(agent, explicit_access)` directly, so the widening guard in `resolve_registry_access_profile` (`src/driver.rs:295-305`) — reachable only from the `Some(agent_config)` branch — never runs for Spawn, and an omitted `access` inherits the *registry* default (`src/agents/mod.rs:222-240`) rather than `agentDefaults`. `SpawnConfig.access` is an unvalidated `Option<String>` (`src/model.rs:411-425`; `:1486-1512` checks only agent/command/cwd), and for an **unregistered** agent `:2172-2179` swallows the unknown-profile error and launches bare argv while `:2182`→`:2122-2123` still stamps `KEY_ACCESS` — a pane labelled with a profile that was never applied. User-visible: the free-text Access field at `InspectorPanel.svelte:1301-1307` reads `placeholder="inherit"` and inherits nothing, and its RunAgent twin at `:782-788` advertises `read_only`/`execute`, neither of which is a valid registry key (`read-only` is).
**Recommended Fix:** Make `resolve_registry_access_profile` the single owner of every access decision by threading the resolved `AgentConfig` into the spawn path.
- Pass `config` from `run_tmux_node` (`src/tmux_exec.rs:286`) through the `:317-319` dispatch into `execute_spawn`, and forward it at `:678` instead of `None`.
- Have `build_agent_command` take the `Some(agent_config)` branch when a Spawn node launches an **agent**, with `SpawnConfig.access` populating `AgentConfig.access_profile_override` exactly as `RunAgentConfig.access` already does. Command-override spawns keep bypassing this via `:2069-2076`.
- **Sequence after M16.** M16 is an open `default`-widening hole inside `resolve_registry_access_profile` (`src/driver.rs:314-321`); routing Spawn into that function before M16 lands inherits the hole.
- Fold the authoring-time half into M6's validator: reject any `SpawnConfig.access` that is not a key of `agent_access_profile_names(agent)` (`src/driver.rs:268-279`) when the agent resolves to a registry entry, warn when it does not, and surface the rejection in the UI.
- Fix the two misleading UI controls: replace the free-text inputs at `InspectorPanel.svelte:1301-1307` and `:782-788` with a select populated from `/api/capabilities` (`accessProfiles`), with an explicit "registry default" option — this also kills the `read_only`-vs-`read-only` footgun.
- Accept the behavioural change: Spawn's argv gains `build_session_args`' model/tool/turn flags. This is a deliberate reversal of the `20260716-003531.md:88-96` M1 ruling ("Leave Spawn's else-branch behavior intact"), which preserved this path as the working reference RunAgent was fixed against; note the reversal in the commit message.
- Add regressions: a Spawn node under `agentDefaults.accessMode: read_only` must not launch with a broader profile; an omitted `access` must inherit `agentDefaults` rather than the registry default; an unregistered agent with an unknown profile must not stamp `KEY_ACCESS`; a command-override spawn must still bypass the ceiling unchanged.
