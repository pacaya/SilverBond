#### Issue H4: Opening/importing a legacy workflow crashes the graph editor
**Severity:** HIGH
**File(s):** `ui/src/features/editor/flowNodes.ts:67,71`; `ui/src/lib/types/workflow.ts:226-229` (required decls), `:520` (`moveV2ConfigField`), `:543-611` (`normalizeWorkflowNode`), `:545-547` (early return), `:588-596` (capture/kill backfill pattern); `ui/src/lib/stores/workflowStore.svelte.ts:76,166`; `ui/src/lib/stores/nodeMetadata.ts:62-64` (`defaultNodeKind`); ingress `ui/src/features/editor/Sidebar.svelte:33`, `ui/src/app/AppShell.svelte:145`
**Description:** Severity rationale: MEDIUM — *lowered from HIGH*: reachable only via browser file import, since the backend always emits these configs; but within that ingress it is a total, unrecoverable loss of the editor. ID retained as `H4` for stability.

`NodeKind` declares `subflowConfig`/`decideConfig`/`batchConfig` as required (`ui/src/lib/types/workflow.ts:226-229`), but `normalizeWorkflowNode` backfills only `captureConfig` (`:588-590`) and `killConfig` (`:594-596`) — `moveV2ConfigField`'s `if (value != null)` guard at `:520` silently drops the rest. A node whose config is absent or `null` therefore survives as `kind = {type:"subflow"}` with no config, and a node already in v4 `kind` shape bypasses normalization entirely through the early return at `:545-547`. `buildFlowNodes` then throws `TypeError: Cannot read properties of undefined (reading 'workflowName')` at `flowNodes.ts:67` inside `GraphEditor`'s `$effect`; because there is **no `<svelte:boundary>` anywhere in `ui/src`**, the whole canvas blanks with no recovery. Two further unguarded dereferences exist at `workflowStore.svelte.ts:76` and `:166`.

*Correction to the original write-up:* the premise that the Rust serializer omits default-valued configs does **not** hold for these three — `src/model.rs:631-646` uses `#[serde(default, rename=…)]` with no `skip_serializing_if`, so the backend always emits them and backfills missing ones on deserialize. Every backend-sourced path (sidebar open, templates, runs) is safe; the sole crashing ingress is browser file import (`Sidebar.svelte:33` `JSON.parse` with arrays-only validation → `AppShell.svelte:145` `duplicateWorkflowForEditing`), which never round-trips through the backend. The required type declaration is therefore truthful for backend data.

*Prior history:* this is a **known-incomplete prior fix**. S19 (`docs/issues/feature-tmux-panes-code-review-20260705-074320.md:467-478`, FIXED, MEDIUM) named `flowNodes.ts:66-71` explicitly and its fix text promised the normalizer would synthesize kind "including the legacy `subflowConfig` reads" — it never backfilled the configs themselves. S19 also explicitly declined a per-node try/catch as the primary remedy.
**Recommended Fix:** Close the gap at the normalizer chokepoint, sourcing defaults from `defaultNodeKind()`.
- In the `decide` / `parallel_batch` / `subflow` / `call` cases of `normalizeWorkflowNode`, fill any missing config from `defaultNodeKind(nodeType)` (`ui/src/lib/stores/nodeMetadata.ts:62-64`), mirroring the existing capture/kill backfill pattern at `:588-596`.
- **Also apply the backfill to already-`kind`-shaped nodes** that currently bypass everything via the early return at `:545-547` — without this, a v4 node with `kind:{type:"subflow"}` and no config still crashes.
- Do **not** source `batchConfig` from `DEFAULT_BATCH_CONFIG` as the original fix text suggested: it is not exported, only a local const inside `InspectorPanel.svelte:225`. Use `defaultNodeKind()` for all three so editor and normalizer cannot drift.
- Verify no import cycle is introduced by `types/workflow.ts` depending on `stores/nodeMetadata.ts`.
- Add normalize regressions for config-less `subflow`, `decide`, and `parallel_batch` nodes; `workflow.normalize.test.ts:57-63` currently covers only capture/kill backfill.

#### Issue M2: Default Send nodes crash compound extraction and fail typechecking
**Severity:** MEDIUM
**File(s):** `ui/src/lib/stores/workflowStore.svelte.ts:175`, `:197` (compare correct sibling handling at `:171`, `:190-193`); `ui/src/lib/stores/workflowStore.test.ts:576-577`; `ui/src/lib/types/workflow.ts:231`, `:581`; `src/model.rs:430-443`, `:652`
**Description:** Severity rationale: MEDIUM (top of band) — sole cause of a red typecheck gate, so it blocks merge outright, and the runtime crash is reachable from ordinary backend data; offset by a trivial repair and the need for one save/reload cycle to hit it.

`ui/src/lib/stores/workflowStore.svelte.ts:175` reads `node.kind.sendConfig.text` and `:197` writes `node.kind.sendConfig.text = text`, both unconditionally, while `NodeKind` declares `sendConfig?: SendConfig` (`ui/src/lib/types/workflow.ts:231`). Two lines above, the sibling `run_agent` branch handles this correctly — `node.kind.runAgentConfig?.prompt ?? ""` (`:171`) with a `?? { killAfter: true }` default before writing (`:190-193`). Verified by running the gate: `npm run typecheck` reports **exactly 4 errors and no others** — `workflowStore.svelte.ts:175:43`, `:197:38`, `workflowStore.test.ts:576:12`, `:577:12`, all `'…sendConfig' is possibly 'undefined'` — so this finding alone is why `just typecheck` / CI is red on this branch. At runtime, a Send node whose text is still empty round-trips from the backend without `sendConfig`, and "Save as compound" over it throws `TypeError` in `compoundNodePromptTexts`, blanking the canvas since `ui/src` contains no `<svelte:boundary>`.

*Premise verified — and note it differs from H4:* the optional declaration here is **truthful**. `src/model.rs:652` carries `#[serde(default, rename = "sendConfig", skip_serializing_if = "is_default")]` over `SendConfig::default() = {target: None, text: "", enter: true}` (`:430-443`), so the backend genuinely omits a default-valued config. This is unlike `subflowConfig`/`decideConfig`/`batchConfig` in H4, which are always emitted — hence the two findings correctly take different fixes. `normalizeWorkflowNode` does not backfill send (`ui/src/lib/types/workflow.ts:581`), unlike capture/kill at `:588-596`.

*Introduced on this branch:* both deref sites and the two test assertions came from `ba9d6e1` ("Harden pane-stream lifecycle and compound extraction boundaries") as the fix for `20260716` M12, were restructured into `compoundNodePromptTexts`/`applyCompoundPromptField` by the S9 fix, and were touched again in `05eb37c`. `sendConfig`'s optionality is long-standing (`12ac692`) — the fix author introduced the mismatch, not the type.
**Recommended Fix:** Guard both sites with optional chaining, matching the sibling `runAgentConfig` handling in the same function.
- At `:175`, read `node.kind.sendConfig?.text ?? ""`.
- At `:197`, write `node.kind.sendConfig = { ...(node.kind.sendConfig ?? { text: "", enter: true }), text }` so the spread preserves `target` and `enter` rather than discarding them.
- Narrow or initialize the optional config in the two assertions at `workflowStore.test.ts:576-577`.
- Confirm `npm run typecheck` reports 0 errors afterwards.
- Do **not** make `sendConfig` required and backfill it in the normalizer (the H4 approach): because `skip_serializing_if` means the field really is absent on the wire, a required type would be a lie for any ingress that bypasses `normalizeWorkflowNode` — the exact flaw H4 exists to correct.
- Follow-up worth tracking separately: `spawnConfig` and `waitConfig` carry the same `skip_serializing_if` and are latent twins of this bug.
