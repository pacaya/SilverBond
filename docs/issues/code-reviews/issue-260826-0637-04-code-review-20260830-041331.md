### H1. Regeneration positive control never exercises the env-gated write path (FIXED)

> **Fix:** Redesigned around a `REGEN_ENV` constant and a single gated entry `regenerate_catalog_at`; the positive control now copies the committed document to a temp tree, perturbs a block on disk and drives that real entry. Both reviewers re-ran the env-var rename mutation and confirmed the suite now reddens in both directions (source rename and justfile-only rename), and that a perturbed block on disk comes back byte-identical with a clean second pass. Residual gaps that the `#[ignore]` introduced are tracked as L8/M5/L9, not as a re-break of H1.

**Severity:** HIGH · **File:** `tests/docs_catalog.rs:639-674` · **Source:** Both (CLAUDE-1, CODEX-3)

The acceptance criterion demands a positive control against "a write mode that silently never writes (mis-named variable, marker-lookup miss, swallowed path error)". `regeneration_writes_to_disk` does not implement it: it perturbs in memory, calls `apply_catalog_to_markdown` in memory, then calls `write_catalog(temp.path(), &repaired)` directly on a `NamedTempFile`. It never copies the tree, never reads back from disk before regenerating, and never touches the `SB_REGEN_DOCS` branch at `tests/docs_catalog.rs:639` or `docs_path()` at `:33`.

Both reviewers proved it by mutation: renaming the gate to `SB_REGEN_DOCZ` leaves all four tests passing, so `just regen-docs` becomes a permanent silent no-op with a fully green suite. The same hole covers a typo in `justfile:76`. The real write path does work — perturbing `docs/workflow-schema.md` on disk and running `SB_REGEN_DOCS=1 cargo test --test docs_catalog node_catalog_generator` repairs it byte-identically — but nothing in the suite protects that.

**Fix:** Route the gate through one named constant and one function (e.g. `const REGEN_ENV: &str = "SB_REGEN_DOCS"`), and have the positive-control test copy the committed document into a `tempfile::TempDir`, perturb it there, and drive the *same gated entry* against that copy, asserting it comes back byte-identical to the committed original. Additionally assert the justfile recipe body contains `REGEN_ENV`, so a rename in one place reddens the suite.
