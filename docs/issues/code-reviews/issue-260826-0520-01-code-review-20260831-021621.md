### H1. Capabilities drift test uses the production generator as its own expected value (FIXED)

> **Fix:** Removed the production tag-helper imports from `tests/http_api.rs`, added a test-local serde enum variant harvester copied from the established technique, and compared both endpoint arrays in exact order against independently harvested `WorkflowNodeType` and `WorkflowEdgeOutcome` vectors.

**Severity:** HIGH · **File:** `tests/http_api.rs:13,1024-1031`; `src/api.rs:214-218` · **Source:** Both (CODEX-2 + CLAUDE-1, merged)

The integration test imports `workflow_node_type_tags()` / `workflow_edge_outcome_tags()` — the exact
helpers the handler calls at `src/api.rs:217-218` — and uses them as the expected side of the
assertion. Actual and expected are one computation, so the assertion reduces to `f() == f()` across an
HTTP round-trip.

Enum→endpoint drift is genuinely impossible now by construction, so this does not recreate the
*original* failure exactly. What it leaves unpinned is the helper itself plus the published wire
strings and their order: if a helper were changed to harvest the wrong enum, or to filter, reorder, or
return a literal subset, both sides would move together and the test would stay green. Renaming
`WorkflowNodeType::RunAgent` silently changes the public payload and desyncs the hand-written TS unions
at `ui/src/lib/types/workflow.ts:3,20` with the whole Rust suite green. Acceptance criterion 5 (payload
preserved) therefore has no instrument at all, and the brief flagged that edge outcomes have no
compile-time backstop, making this criterion the only cover for that half.

This also diverges from the Context Pack's explicit instruction: "Harvesters live in an integration-test
crate, so the technique is copied/extracted, not imported."

Both reviewers reached this independently; Claude initially rated it MEDIUM and deferred to Codex's HIGH
on cross-verify.

**Fix:** Define a test-local harvester inside `tests/http_api.rs` (copy the technique, per the Context
Pack) rather than importing the production helpers, and compare the endpoint arrays in exact order
against those independently harvested vectors.

### M1. A failed capabilities fetch renders "Loading…" forever and leaves the editor unusable (FIXED)

> **Fix:** Derived `capabilitiesQuery.isError` in `AppShell.svelte`, threaded it through `GraphEditor` and `InspectorPanel`/`EdgeInspector`, and rendered distinct "Node types unavailable." / "Outcomes unavailable." affordances on fetch failure while retaining loading text for pending requests. **Severity:** MEDIUM · **File:** `ui/src/app/AppShell.svelte:48,108`; `ui/src/features/editor/GraphEditor.svelte:269`; `ui/src/features/editor/EdgeInspector.svelte:53` · **Source:** Claude (Codex AGREE on cross-verify)

indistinguishable from a slow one, and no error is surfaced anywhere.

**Fix:** Thread the query status (or `capabilitiesQuery.isError`) down alongside the data and render a
distinct unavailable/retry affordance in both components, keeping the pending text for the genuinely
pending case.
