### LOW-1. Sole surviving guard is coupled to the validator's message wording (dismissed: mandated by the brief, and guarded by superstring unit assertions)

**Severity:** LOW · **File:** `tests/docs_catalog.rs:582` · **Source:** Claude

After the deletion, the substring filter `issue.message.contains("so task execution fields
are ignored")` is the only enforcement that catalog examples keep task-execution fields off
`Split`/`Collector` nodes. It is coupled by string to the validator's format string at
`src/model.rs:1937-1940`. Claude's concern: reword that message and the filter matches
nothing, `ignored_warnings` is unconditionally empty, and the assertion passes vacuously
forever — trading one silent-drift mode (stale field list) for another (stale phrase).

**Adjudication (orchestrator read the code):** dismissed as a defect in this diff, on two
independent grounds.

1. *The coupling is the contract, not a regression.* The Agent Brief's **What to do**
   mandates it verbatim: "Leave the assertion that filters validation issues for the
   ignored-task-fields warning phrase unchanged. It becomes the sole enforcement of this
   property." The diff did exactly that. A finding against it is a finding against the
   gated brief, not against the implementation.
2. *The drift mode is already guarded.* Verified at `src/model.rs:3982` and `:3987`: the
   validator's own unit tests assert on `"split node, so task execution fields are ignored"`
   and `"collector node, so task execution fields are ignored"` — strict superstrings of the
   docs-catalog filter. Any reword of the format string at `src/model.rs:1938` fails those
   two assertions loudly before it can silently deaden `tests/docs_catalog.rs:582`.

The recommended fix (hoist the phrase to a shared `pub(crate)` constant in the validator
module) would also widen a validator internal for the test's benefit — the same move the
brief's **Out of scope** rejects for the predicate. The residual is recorded on the design
axis under Smells rather than fixed here.
