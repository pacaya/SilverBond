### L1. Order test asserts label text only, never that a control renders (FIXED)

> **Fix:** added `fieldControlsPresentInSection`, which maps each `label.field` in the located section to whether it contains an `input`, `select`, or `textarea`; both order tests now assert `.every(Boolean)` is true. A component rendering its `<span>` but losing its control now fails.

**Severity:** LOW · **File:** `ui/src/features/editor/InspectorPanel.test.ts:491` · **Source:** Claude (Codex DISAGREE — adjudicated in favour of the finding)

`fieldLabelsInSection` collected only `label.field > span:first-child` text, so a regression dropping an `<input>` from an extracted component still yielded the exact expected label sequence and passed. Codex disagreed on the grounds that control completeness is a separate source-survey criterion; that is true of the acceptance criteria, but the record itself leans on the order test as "the real functional guard", so strengthening it serves the record's own stated reliance at negligible cost.

**Residual, accepted:** `Array.prototype.every` returns `true` on an empty array. Both reviewers confirmed the hole is unreachable today — `label.field > span:first-child` selects a strict subset of `label.field`, so a passing 9-element (resp. 7-element) label assertion guarantees a non-empty control array, and the label assertion executes first. The closure is implicit rather than structural, and `.every(Boolean)` collapses to one boolean that does not name which field lost its control. Not raised as a finding by either reviewer; recorded here as known test-robustness polish.

**Fix:** assert each `label.field` contains a control element.
