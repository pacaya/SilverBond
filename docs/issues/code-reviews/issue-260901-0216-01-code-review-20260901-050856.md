### C1. Validation-catalog Source-column citations (~152 table rows) are silently skipped (FIXED)

**Severity:** CRITICAL · **File:** `tests/docs_catalog.rs:1012`, `docs/workflow-schema.md:1609-1761` · **Source:** Both

> **Fix:** Discovery is now mention-driven with a `claimed[]` coverage vector; both reviewers re-ran the Source-cell perturbation and it goes red. Coverage went from 76 recognised citations to 302 candidates over 303 mentions, with exactly 1 classified as prose.

`extract_citations` recognises only two shapes: a parenthesised body, and the `` `sym` in `file` ``

comma-separated backtick run, e.g. `docs/workflow-schema.md:1673` reads
`` `validate_graph_body`, `src/model.rs`, `Duplicate node id` ``. With no `(` there is no match, and

the brief forbids — "Skipping and resolving must never be indistinguishable to an observer" — and it
exempts the largest and most drift-prone citation block in the document.

**Fix:** Recognise the table-cell shape, and add a total-coverage assertion: every backticked
`src/*.rs` occurrence outside generated blocks must be claimed by some citation or explicitly
classified as prose, so a whole silently-skipped class cannot recur.

### C3. Unparseable citations are treated as prose, and surplus grammar tokens are dropped (FIXED)

**Severity:** CRITICAL · **File:** `tests/docs_catalog.rs:892`, `:923`, `:960` · **Source:** Both

> **Fix:** Discovery and parsing are separated; parsing tokenises once, requires exactly one source file, and rejects surplus tokens. All four previously-skipped malformed shapes now report `unparseable citation:`, and the fixtures use non-positional malformed shapes.

Three linked defects defeat the brief's "any citation the guard cannot parse is reported, not
skipped" requirement:

1. `paren_body_is_citation` returns false the moment a paren body does not start with a backtick, and
   `extract_citations` then advances one character with no diagnostic. `docs/workflow-schema.md:1071`
   contains `` (10, `MAX_NODE_RETRY_COUNT`, `src/model.rs`) `` — a real citation, invisible; renaming
   that symbol left the suite green. The `` `error` ``-severity paren body at
   `docs/workflow-schema.md:1604` is rejected the same way (Codex cited 1564; Claude corrected the
   line to 1604 on cross-verify).
2. Only `tokens[file_pos + 1]` is taken as the discriminant, with no check that
   `tokens.len() == file_pos + 2`. `docs/workflow-schema.md:1457` carries five tokens; three are
   discarded without comment.
3. The only `Unparseable` trigger (`tests/docs_catalog.rs:945`) fires solely for tokens containing
   `.rs:` or a leading `:` — exactly the two shapes the fixture plants. The unparseable criterion is
   therefore tautologically tied to the grammar being removed rather than testing the guard's
   handling of shapes it genuinely does not understand.

**Fix:** Separate candidate discovery from parsing: treat any paren body or table cell containing a
`src/*.rs` backtick token as a citation candidate, require the parser to consume it entirely, and
emit `Unparseable` for unmatched punctuation, bad separators, or trailing tokens. Add fixtures for
malformed shapes that are *not* the removed positional form.

### H1. The hand-rolled Rust index is both unsound and incomplete (FIXED)

**Severity:** HIGH · **File:** `tests/docs_catalog.rs:1086`, `:1130`, `:1173`, `:1180`, `:1199`, `:1265` · **Source:** Both

`index_rust_source` misses real symbols and invents fake ones, so both halves of the missing-symbol
guarantee fail:

- **False negatives.** The top-level function cascade strips only `pub async fn` / `async fn` /
  `pub fn` / `fn`, so `pub(crate) fn` items are not indexed at all. `validate_workflow_input_bounds`
  (`src/model.rs:1491`) and `max_node_retry_attempts` (`src/model.rs:20`) return zero spans.
  `docs/workflow-schema.md:1601` cites the former and is currently invisible only because of C2 —
  **fixing C1/C2 without this turns the suite red.**
- **False positives.** The enum loop treats every identifier-leading line inside an enum body as a
  variant, inventing `NodeKind::default`, `NodeKind::rename`, `NodeKind::skip_serializing_if`,
  `NodeKind::agent_config`, `NodeKind::decide_config`, `NodeKind::batch_config`,
  `NodeKind::subflow_config` from wrapped `#[serde(...)]` attribute lines and struct-variant fields.
  Nonexistent symbols therefore resolve.
- **`static` items are not indexed** although the brief names statics as a citable kind.
- **`#[cfg(test)]` modules are indexed.** There is no `mod` handling, so the walker runs straight
  through `src/model.rs:3291`, `src/runtime.rs:1739` and `:7416`, `src/api.rs:2750`. Verified:
  `index_rust_source("src/model.rs")` yields a span named
  `compute_graph_metadata_includes_parallel_batch_body_entry` (a test fn). `check_citation` also
  searches whole-file text including tests when classifying MissingDiscriminant vs
  DiscriminantOutsideSymbol, so a literal existing only in tests is misclassified as out-of-extent.
- **`brace_extent` operator precedence.** `col < line.len() && (…).is_ascii_alphanumeric() || … == '_'`

  corrupts that symbol's extent and, via the `i = end + 1` jumps, every symbol after it.
- **Enum brace column fallback.** `lines[i].find('{').unwrap_or(i)` passes the *line* number as a
  *column*. (Codex DISAGREEd, noting the scan recovers on the following line; orchestrator kept it at
  LOW-within-this-cluster — wrong by construction and inside the code this fix must rework.)

**Fix:** Rework item recognition to be visibility-agnostic and structurally aware: accept any
visibility prefix, index `static`, stop at `#[cfg(test)]`, accept only real enum variants (track brace
depth, skip attribute lines), fix the precedence bug, and skip `//` to end of line in `brace_extent`.
No new dependency is available — the parent PRD's stack row ratifies zero new dependencies, so `syn`
is not an option. Add negative fixtures for the current false-positive enum names and a resolving
fixture for the cited `pub(crate)` function.

### H4. The document-wide perturbation fixture makes the whole Rust suite ~30x slower (FIXED)

**Severity:** HIGH · **File:** `tests/docs_catalog.rs:2188` · **Source:** Both

> **Fix:** Round 3: the quadratic fixture and its `corrupt_citation_first_symbol` helper were deleted outright; P2 is now carried structurally by `citation_raw_identifiers_are_unique` (one extraction, set comparison, ~2s). `citation_perturbations_produce_distinct_locatable_diagnostics` loops over all 302 candidates and calls

### L10. The rendered slice and the reported column disagree for externally-symbolled citations (FIXED)

### M9. The shared source-cache mutex is held across the entire sweep, serializing the fixture set (FIXED)
