### H1. Dead-end metadata and the terminal-node warning are falsely described as different predicates (FIXED)

**Severity:** HIGH · **File:** `docs/workflow-schema.md:1575-1578` · **Source:** Both (CLAUDE-1 / CODEX-1, mutual AGREE)

> **Fix:** Rewrote the graph-metadata paragraph: the root dead-end and terminal predicates are stated to coincide, and the asymmetry is recast as root-only `deadEndNodeIds` vs terminal warnings also emitted inside every catalogued subflow body. Both reviewers verified against `src/model.rs:3153-3158`, `:1915-1922`, `:215-221`, `:2526-2533`. (The rewrite introduced one off-by-one citation — see `L9`.)

The preamble asserts that a node listed in `deadEndNodeIds` "is not necessarily warned about" because
the terminal-node warning "is a different predicate". The two predicates coincide exactly over the
root graph. `compute_graph_metadata` collects a dead end iff `graph.outgoing_for(&node.id).is_empty()`
(`src/model.rs:3153-3158`); the terminal warning fires iff `branch_edges == 0 && loop_edges == 0 &&
success_edges == 0 && reject_edges == 0` (`src/model.rs:1915-1922`) over the complete five-variant
`WorkflowEdgeOutcome` (`src/model.rs:215-221`). Every root node in `deadEndNodeIds` *is* warned.

This is an over-correction of precisely the mislabelling the slice existed to fix: the superseded
document called the terminal warning a dead-end warning, and the replacement now denies a
relationship that does hold.

**Fix:** Keep the metadata-versus-issue distinction (which is correct and required by the brief), but
state that the root dead-end and terminal predicates currently coincide. The genuine asymmetry runs
the other way and should replace the false one: `deadEndNodeIds` is computed for the root document
only (`src/model.rs:1467`), while the terminal warning is additionally emitted inside every
catalogued subflow body (`validate_graph_body` re-entered per subflow, `src/model.rs:2526-2532`).

### H3. Command-driven `spawn` nodes bypass `access` validation entirely (FIXED)

**Severity:** HIGH · **File:** `docs/workflow-schema.md:1713-1723` · **Source:** Both (CLAUDE-4 / CODEX-5, mutual AGREE)

> **Fix:** The agent-launch preamble now separates `extraArgs` (validated on both kinds) from `access` (validated on `run_agent` and only on agent-launched `spawn` nodes without a non-blank custom `spawnConfig.command`), citing `src/model.rs:1734-1736`. Verified by both reviewers.

The prose states that `extraArgs` and `access` on `spawn` and `run_agent` nodes are validated by
