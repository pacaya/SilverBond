### H1. `contextSources` documents a wire shape that cannot deserialize (FIXED)
> **Fix:** type cell now `array of {name, nodeId}` with `ContextSource` (`src/model.rs:121-126`) cited and `nodeId` described; both reviewers re-verified the shape and citation.

**Severity:** HIGH · **File:** `docs/workflow-schema.md:1069` · **Source:** Both

The common table types `contextSources` as ``array of `{name, source}` ``. The actual element type
is `ContextSource` (`src/model.rs:121-126`): `name: String` and `node_id: String` under
`#[serde(rename_all = "camelCase")]`, so the wire keys are `name` and `nodeId`, and neither field
carries `#[serde(default)]` — both are hard-required. `src/runtime.rs:7119` destructures
`ContextSource { name, node_id }`. `{name, source}` is `InputBinding`'s shape (`src/model.rs:430-435`),
correct for `decideConfig.inputs` and `subflowConfig.inputs` but copy-pasted onto the wrong row.

No struct in the tree uses `deny_unknown_fields`, so a reader copying the documented shape has the
stray `source` key silently dropped and the deserialization fails on missing `nodeId` — the
reference hands out an unusable wire contract for the one field it is meant to pin.

**Fix:** Change the type cell to ``array of `{name, nodeId}` ``, describe `nodeId` as the referenced
node identifier, and cite `ContextSource` (`src/model.rs:121-126`).
