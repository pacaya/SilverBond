**Severity:** HIGH · **File:** `templates/research-and-summarize.json:53,69` · **Source:** Both · **Round 1:** payload half fixed, cluster escalated

**Same-site escalation, round 1 → round 2.** This finding began as "decide hop discards the research payload on both newly reachable paths". The round-1 fix re-plumbed rs2 and rs3 with `contextSources` bindings, and the payload half genuinely landed — both reviewers confirmed `{{context:research}}` resolves on both paths, because rs1 executes on every path. But the fix introduced a new defect in the same region, and re-verification split: Claude returned VERIFIED_FIXED and filed the residuals as fresh findings; Codex returned STILL_BROKEN naming the same residuals as unfinished halves of H1. Per the same-site escalation rule the patch and the findings are the same code disagreeing with itself, so **CODEX-4, CLAUDE-12 and CLAUDE-13 are folded into H1 as one defect** rather than tracked as three, and round 2 switches from patching to redesigning the region.

**The mechanism to remove.** Every input slot in rs2's and rs3's prompts is filled by a placeholder whose resolution depends on which nodes happened to execute, and the two forms fail in opposite directions:

- `{{context:<name>}}` substitutes **only when the bound node has a result** (`src/runtime.rs:7091-7094` — a plain `if let Some(result)`, with no `else` and no cleanup pass afterwards; the function ends at `:7124`). A binding to a node that did not execute leaves its literal token in the prompt.
- `{{previous_output}}` (`src/runtime.rs:7097`) and `{{all_predecessors}}` (`:7107-7124`) **always** substitute, so when the nearest executed predecessor is the decide node they render its outcome label as content — `apply_join_result` assigns `last_output` from every completed node with no decide special-case (`src/runtime.rs:4476`).

Both consequences are live in the shipped template:

- **Unresolved literal (CODEX-4 · CLAUDE-12, both reviewers, independently).** rs3 binds `refined` to rs2, but the Quick summary edge reaches rs3 without executing rs2, so the quick-path prompt is sent to the model as `…{{context:research}} resolved…

{{context:refined}}` — a raw placeholder in a bundled example, on the very path this issue exists to make reachable.
- **Routing label as content (CLAUDE-13).** rs2 retains `{{previous_output}}` for loop chaining, which is correct from iteration 2 onward but renders the literal `Deep dive` on iteration 1. Residual noise rather than payload loss, but the same mechanism.

Note the engine is asymmetric here: the field-path forms `{{node:<id>.output.<field>}}` and `{{node:<id>.parsedOutput.<field>}}` `unwrap_or_default()` to empty (`src/runtime.rs:7058-7064`, `:7081-7087`), while both `{{context:<name>}}` and the plain `{{node:<id>.output}}` (`:7042`) are gated on the node having a result. Repairing that asymmetry is Rust templating code and is **out of scope** — the brief forbids engine changes, so the redesign must be template-only.

**Checkable properties the redesign must satisfy** (judging "is the mechanism gone?" from prose is how a redesign ships fresh defects — assert these, do not claim them):

1. **P1 — no conditionally-resolving binding.** No node's prompt in this template contains a `{{context:<name>}}` whose bound node is absent from the executed set on any path that reaches that node.
2. **P2 — no unresolved token on any path.** For each decide outcome, every executed node's resolved prompt contains no residual `{{…}}` token.
3. **P3 — payload preserved.** rs1's research still reaches rs2 on the Deep dive path and rs3 on the Quick summary path — the round-1 gain must not regress.
4. **P4 — slots are self-describing.** Every remaining always-resolving slot is introduced by label text, so a routing label landing in one reads as a labelled field rather than dangling prose.

**Fix:** Template-only. Give rs3's refinement slot an always-resolving form under an explicit label instead of the execution-optional `{{context:refined}}` binding, keep `{{context:research}}` (rs1 is on every path, so it always resolves), and label rs2's trailing slot the same way. There is no template-only placeholder that yields rs2's output on the deep path and nothing on the quick path — the field-path forms that empty out require JSON output rs2 does not produce — so the honest target is "no unresolved token ever ships, and whatever lands in a slot is legible", not "the quick path renders an empty refinement section". State that limit rather than papering over it.

**Assert P1/P2 with an adversarial fixture, not a prose claim.** A pure graph-plus-string computation over the template JSON discharges both with no engine call: for each decide outcome, derive the set of nodes executed on that path, then assert that every `{{context:<name>}}` in those nodes' prompts binds into that set and that no `{{…}}` token survives substitution of the resolvable ones. It is red today on the quick path (rs3 binds rs2 ∉ {rs1, rs-decide, rs3}) and green after the redesign. Scope it to this template as its own test function — do **not** fold it into the corpus guard as a new corpus-wide rule, which is the scope expansion L8 was dismissed for.
