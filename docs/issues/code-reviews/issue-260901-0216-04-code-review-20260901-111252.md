### M1. Documentation asserts a key/node-id correspondence that nothing enforces (FIXED)

> **Fix:** The unqualified parenthetical is replaced with an explicit non-enforcement statement: keys
> are described as *intended* to match `nodes[].id`, followed by "that correspondence is not validated —
> an entry whose key no longer names a node in `nodes[]` is neither rejected nor pruned and round-trips
> unchanged." Both reviewers re-verified against the code rather than the wording — `grep -rn "canvas" src/`
> still yields one hit outside the type definitions, and every `.ui` reference is a construction site or a
> `None` test fixture — and returned VERIFIED_FIXED.

**Severity:** MEDIUM · **File:** `docs/workflow-schema.md:1430-1431` · **Source:** Both (CLAUDE-1 / CODEX-1, both AGREE)

The new section describes the map as keyed by node id "(strings matching `nodes[].id` in the same
workflow body)". Unqualified, that reads as an enforced constraint. Nothing enforces it:
`WorkflowCanvasUi::nodes` is a plain `BTreeMap<String, WorkflowCanvasNodeState>` carrying only
`#[serde(default, skip_serializing_if = "BTreeMap::is_empty")]`, and no validator, migration, or
`ensure_defaults` path inspects canvas keys. A stale or arbitrary key deserializes and round-trips
unchanged. The frontend's id remap preserves unmapped keys verbatim, so orphan entries are reachable
in practice, not merely theoretical.

This is the spec-axis defect on a record whose whole subject is documentation truth. The document has
an established voice for unchecked constraints — "Root-level variable names are not checked for
uniqueness" (`docs/workflow-schema.md:1397`) — so the unqualified phrasing deviates from the
document's own standard.

**Severity adjudication:** Claude argued MEDIUM (only spec-axis defect; deviation from the document's
stated convention; practically reachable). Codex argued LOW (blast radius is ignored editor-layout
metadata — no validation, execution, security, or node-data impact). Adjudicated **MEDIUM**: on a
documentation-truth record the axis, not the blast radius, anchors severity — a false claim about
what the code enforces is the exact failure mode this issue exists to remove. Both reviewers'
recommended fixes are substantively identical.

**Fix:** Qualify the key description — state that keys represent node ids and that the backend does
not validate the correspondence: an entry whose key no longer names a node in `nodes[]` is neither
rejected nor pruned and round-trips unchanged. Cite the absence the way the variables paragraph does.

### L4. Non-finite position serializes to `null` and then fails to reload (deferred)

**Deferred:** the record's Out of scope is explicit — "Any change to the types themselves, their
serialization, or their defaults." Claude filed it as a follow-up flag, not a change request, and it
is not a defect in this diff. Worth a separate record against `WorkflowCanvasNodeState` /
`WorkflowCanvasViewport` for non-finite handling.
