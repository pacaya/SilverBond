### H1. Run event streaming is blocked by the new Origin middleware (FINALIZED)
**Severity:** HIGH — breaks the core run-streaming flow (events/approvals/interactions) in every non-Tauri context; masked only in the packaged app.
**Files:** `src/api.rs:93-99`, `src/api.rs:133-142`, `ui/src/lib/api/client.ts:91-98`, `ui/src/app/AppShell.svelte:186-237`
**Description:** `stream_routes` wraps both the SSE route `/api/runs/{run_id}/stream` and the pane WebSocket route in `require_allowed_stream_origin` (`src/api.rs:93-99`), which returns `403` whenever the `Origin` header is absent (`src/api.rs:139-140`). In `startRun`/`resumeRun`/`restartFromNode` (`ui/src/app/AppShell.svelte:186-237`) the `catch` reports "Run failed" and the `finally` clears `runId` while the backend run keeps executing — the user loses all live events, approvals, and interaction prompts. This is a regression of prior finding H7 (the middleware was added in commit `6f35905` on the false assumption that browsers always send `Origin` on SSE handshakes).
**Fix:** Differentiate WS upgrades from GET/SSE inside the origin gate (branch within `require_allowed_stream_origin` or split into two layers). WS upgrades keep the strict allowlisted-`Origin` requirement, preserving the H7 anti-CSWSH protection. For SSE/GET, allow a missing `Origin` when `Sec-Fetch-Site` is `same-origin` or `none`, while still rejecting `cross-site`. Add the currently-missing HTTP-level test exercising `/api/runs/{id}/stream` with no `Origin` header (and a cross-site case) so the branch doesn't silently rot.

### M7. `resolve_tmux_bin` interactive-shell parse is not banner-robust and has no timeout (FINALIZED)
**Severity:** MEDIUM — the interactive flag is intentional (see fix); the real defects are the non-robust whole-output parse and the missing timeout. Corruption needs an interactive rc that prints to stdout; the no-timeout thread-park needs a blocking rc.
**Files:** `src/tmux_exec.rs:93-118`, `src/tmux_exec.rs:97`, `src/tmux_exec.rs:101` (`zsh -lic`), `src/tmux_exec.rs:112` (whole-output `.trim()`), `src/runtime.rs:2607-2625`, `src/runtime.rs:2065-2067` (cached once per run)
**Description:** `resolve_tmux_bin` shells out via `zsh -lic command -v tmux` (`src/tmux_exec.rs:97`/`:101`). The `-i` (interactive) flag is **deliberate and load-bearing**: zsh sources `.zshrc` only for interactive shells, and the operator's (and `run_as` target's) tooling PATH — nvm/pyenv/asdf/Homebrew shims, etc. — lives there; a login-only `-lc` shell would silently fail to resolve tmux on those setups. The actual defects are: (ii) `.trim()` on the whole stdout (`:112`) folds any rc banner output into the resolved path (e.g. `"Welcome!\n/usr/bin/tmux"`), and the not-found case (empty `command -v`) would yield a banner line as a false positive; and (iii) the `.output()` call has no timeout while running inside `spawn_blocking`, so a blocking rc parks a blocking-pool thread indefinitely. The result is cached once per run (`runtime.rs:2607-2625`, `:2065-2067`), so a corrupted value poisons every tmux op (spawn/capture/send/kill) for that run. (This finding recurred across the 06-10 and 06-20 reviews precisely because the `-i` looks like a bug in isolation.)
**Fix:** Keep `zsh -lic` (do **not** drop `-i`). Wrap the lookup in a unique sentinel and extract that line — e.g. `zsh -lic 'print -r -- "SBTMUX:$(command -v tmux)"'` — then find the single line starting with `SBTMUX:`, strip the prefix; an empty suffix means not-found → fall back to `"tmux"`. This is robust against rc banner output appearing anywhere in the stream and correctly distinguishes not-found from banner noise. Wrap the spawn in a bounded wait (kill on deadline, fall back to `"tmux"`). **Add a load-bearing inline comment** at `src/tmux_exec.rs:97`/`:101` stating that `-i` is intentional (zsh sources `.zshrc` only for interactive shells; tooling PATH lives there) and that the historical "rc-stdout-corrupts-path" concern is handled by the sentinel parse — so the flag must not be removed. Record the same decision in a short ADR / decision note so reviewers don't re-flag or silently revert it. Add a test for `resolve_tmux_bin` parsing (banner-prefixed output, not-found, and timeout-fallback cases).
