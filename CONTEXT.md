# Context

Ubiquitous language for SilverBond — the workflow engine that runs LLM CLIs and scripted steps as node/edge graphs. Single context; seeded by RDMP-260815-2009-01, grows with the work.

**Reading this file.** An unmarked entry's definition is true of `src/` at HEAD. An entry marked `_(planned — ADR-…)_` is defined by that ADR instead: the codebase does not yet exhibit it — the engine does not accept it, or the practice is not yet in force — and the marker comes off in the epic that makes it real. Every epic that changes the schema, or that establishes a practice the codebase must follow, owns the terms its ADR names — `grep '(planned' CONTEXT.md` is the outstanding list.

## Language

### The workflow document

**Workflow** [aggregate] — a versioned node/edge graph definition (schema `version: 4`; v2–v3 documents normalize forward at ingest), including its subflow catalog. _Avoid_: pipeline, flow. ↔ src/model.rs:10, :939 (`WorkflowV3`). Decisions: ADR-260815-2009-01 (bumps to v5)
**Workflow Contract** [VO] _(planned — ADR-260815-2009-01)_ — a workflow's declared, typed inputs and outputs (`string | number | boolean | enum | json`, `required` flags); the callee owns it, callers are validated against it. _Avoid_: signature, interface.
**Node Kind** [VO] — the fourteen-variant tagged union in a node's required `kind` object, selecting both what the node does and which config shape it carries; the bare `type` tag alone is what `/api/capabilities` publishes as `supportedNodeTypes`. _Avoid_: step type. ↔ src/model.rs:695 (`NodeKind`), :159 (`WorkflowNodeType`)
**Edge Outcome** [VO] — the channel an edge is traversed on: `success | reject | branch | loop_continue | loop_exit`, the complete set — there is no failure channel, so a node failure always ends its cursor, and outside a split family it fails the whole run and cancels every other cursor. Split-family membership is sticky: a cursor that has ever been enrolled keeps the in-split treatment for the rest of the run. _Avoid_: edge type, transition; calling a node failure terminal for its cursor alone. ↔ src/model.rs:215 (`WorkflowEdgeOutcome`), src/runtime.rs:6226 (`handle_terminal_cursor_status`), :6286 (the whole-run conditional). Decisions: ADR-260815-2009-02 (adds a sixth, `failure`)
**Failure Outcome** [VO] _(planned — ADR-260815-2009-02)_ — the edge outcome taken when a node fails or a condition routes on missing data; taken only where a failure edge is declared, terminal otherwise.
**Condition** [VO] — the engine's single post-execution deterministic branching form (edge and loop conditions): one flat `{field, operator, value}` leaf over a dot-path field, evaluated by the engine and never by an LLM; the pre-execution `skipCondition` is a separate form. _Avoid_: expression, rule. ↔ src/model.rs:130 (`StructuredCondition`), :3182 (`evaluate_condition`). Decisions: ADR-260815-2009-02 (replaces it with a nested `all`/`any`/`not` AST over typed-operator leaves)
**onMissing** [VO] _(planned — ADR-260815-2009-02)_ — a condition leaf's declared policy (`treat-as-false | error | route`) for a field the upstream output never emitted; parse failure evaluates as all-fields-missing.
**Skip Condition** [VO] — a node's pre-execution guard (`{source, type, value}`, `type` one of `contains | not_contains | regex`) that skips the node without running it; an unknown type evaluates false silently, and an invalid regex fails the run before any node executes. _Avoid_: condition (bare — that is the post-execution form). ↔ src/model.rs:138 (`SkipCondition`), src/runtime.rs:2702
**Template Token** [VO] — one of the ten `{{…}}` substitution forms the engine resolves in prompt text — binding sources are a separate, brace-free grammar over the same names; nothing errors on a miss — the two dot-path forms substitute the empty string, while the four name-keyed forms are left in the prompt verbatim. ↔ src/runtime.rs:7035 (`resolve_template_vars`)
**Variable** [VO] — a named, string-valued piece of per-execution state scoped to a cursor; distinct from node results, which are the default data path. ↔ src/model.rs:115 (`WorkflowVariable`), src/runtime.rs:223 (`var_map`). Decisions: ADR-260815-2009-01 (makes it JSON-valued)
**Assignment** [VO] _(planned — ADR-260815-2009-05)_ — a binding-evaluated, cursor-local mid-run variable write (`assignVars`); never an arbitrary expression.
**Boundary Normalization** [service] _(planned — ADR-260815-2009-01)_ — parsing and validating externally-supplied values (run-start overrides, subflow inputs, script outputs) against declared types exactly once, at entry.
**Script Node** [entity] _(planned — ADR-260815-2009-03)_ — a synchronous, non-pane node running static interpreter source (`sh` first) with env-var inputs, stdout+parse output, and exit-code-only success.
**Subflow** [entity] — a workflow invoked as a callable block from another workflow via a call frame. _Avoid_: sub-workflow, child workflow. ↔ src/runtime.rs:3445 (`handle_subflow_node`)
**Validation Issue** [VO] — one entry in a workflow validation result: `{severity, nodeId?, scope?, message}`, where `severity` is an unconstrained string the engine only ever sets to `error` or `warning` — there is no `info` severity — and `scope` names the subflow a nested issue came from; graph metadata rides the result alongside the issues rather than as one. Validation is advisory where it is requested and enforced only at run start — saving a workflow never runs it — and a version rejection is an ingest error that never reaches this channel at all. _Avoid_: save-time validation (saving does not validate), validation error as a name for the whole set (warnings are issues too), lint. ↔ src/model.rs:973 (`ValidationIssue`), :1003 (`ValidationResult`), src/api.rs:751 (run-start enforcement)

### Running a workflow

**Run** [aggregate] — one execution of a workflow, with its own frozen workflow snapshot, variables, and checkpoint; many runs of one workflow may exist concurrently. _Avoid_: job, instance. ↔ src/runtime.rs:730 (`PersistedRun`)
**Run Status** [VO] — the lifecycle state of a whole Run: `running | paused | completed | failed | aborted | restarted`, of which `paused` is never assigned outside tests — a run blocked on approval stays `running`. _Avoid_: run state. ↔ src/runtime.rs:463 (`RuntimeStatus`)
**Checkpoint** [VO] — the serialized full state of a run persisted after every significant transition; the sole authority for resume and restart. ↔ src/runtime.rs:560 (`RuntimeCheckpoint`)
**Execution Epoch** [VO] — the per-run counter that restart increments, stamped on every cursor, split family, and Barrier Key. Nothing in production reads a cursor's or a split family's stamp: restart also clears the split-family and barrier maps and mints a new run id, so no pre-restart state survives for the epoch to fence. Its one discriminating use is on resume, where a legacy epoch-0 checkpoint migrates to 1 without clearing barriers, stranding arrivals keyed at 0. _Avoid_: describing it as the guard that stops pre-restart state satisfying a later barrier — the clear does that. ↔ src/runtime.rs:575, :1480 (`restart_from`), :1509 (the increment), :2263 (the epoch-0 resume migration)
**Cursor** [entity] — an independent execution pointer inside a run, carrying its own variable scope and call stack; splits create cursors, collectors join them. ↔ src/runtime.rs:201 (`CursorState`)
**Cursor Runtime State** [VO] — the live state of a Cursor: `runnable | running | waiting_collector | waiting_approval`; it has no terminal variants, because a finished cursor is removed from the run's cursor list rather than marked. _Avoid_: cursor status. ↔ src/runtime.rs:159 (`CursorRuntimeState`), :2874
**Cursor Terminal Status** [VO] — how a cursor ended — `success | failure | timeout | cancelled` — recorded only on its Collector Barrier arrival, never on the cursor itself. `timeout` is live; `cancelled` is never constructed anywhere in `src/` and survives only as a collector-summary counter that always reads zero. _Avoid_: treating `cancelled` as a state a run can reach. ↔ src/runtime.rs:169 (`CursorTerminalStatus`), :249 (`CollectorInputStatus.status`), :4577, :4816 (the two `timeout` constructions), :6016 (the always-zero `cancelled` counter)
**Node Result** [entity] — the record one node execution writes — output, stderr, exit code, parsed output, timing, agent metadata — into the run-global result map at root scope, or into the cursor's innermost Call Frame `subflow_results` namespace inside a Subflow; replaced when a loop re-executes the same node. Split siblings at root scope therefore share one map, while inside a subflow each carries its own. _Avoid_: node output (that is one field of it); its cursor's result map (true only inside a call frame). ↔ src/runtime.rs:88 (`NodeResult`), :2553 (`results_for_cursor`), :2639 (`insert_result_for_cursor_index`)
**Runner Kind** [VO] — a Node Kind the scheduler dispatches into its concurrent `JoinSet`: `task`, `decide`, `spawn`, `send`, `wait`, `capture`, `kill`, `run_agent`. _Avoid_: dispatch tier. ↔ src/runtime.rs:2086 (`is_runner_node_kind`), :2936
**Immediate Kind** [VO] — a Node Kind resolved synchronously inside the scheduler loop: `approval`, `split`, `collector`, `parallel_batch`, `subflow`, `call` — so a batch's entire fan-out blocks that loop while it runs. _Avoid_: dispatch tier. ↔ src/runtime.rs:3113 (`process_immediate_cursors`)
**Execution Log** [entity] — the per-run record of node executions, decisions, and transitions accumulated on the checkpoint as the run proceeds and persisted separately at finalize. _Avoid_: audit log, history. ↔ src/runtime.rs:607, :536 (`ExecutionLog`), :6631
**Runtime Event** [VO] — one item in a run's event stream: an unconstrained `kind` string (wire name `type`), a flattened data map, and a monotonic `seq` stamped when the event is appended to the run's event table — the `seq` is what makes the SSE stream resumable. _Avoid_: log entry (that is the Execution Log), message. ↔ src/runtime.rs:54 (`RuntimeEvent`), :6985 (`emit_event`)
**Stagnation Detection** [service] — the guard that aborts a run when one node produces three consecutive identical outputs, tracked by rolling hash on a run-global map keyed by call-frame path plus node id. The cursor id never enters the key, so at root scope it is the bare node id and every cursor reaching that node shares one three-slot window; the abort clears every cursor, not just the offending one. Parallel-batch cursors are excluded. _Avoid_: cursor-scoped node key. ↔ src/runtime.rs:41 (`STAGNATION_WINDOW`), :591 (`output_hashes`), :2657 (`scoped_output_hash_key`), :2670 (`record_output_hash`), :4615 (the abort)

### Concurrency, joins, and calls

**Split Family** [entity] — the group a Split's child cursors are enrolled in, carrying the failure policy that decides what one member's failure does to its siblings; a cursor joins one family per enclosing split, and a policy applies across every family it belongs to. ↔ src/runtime.rs:238 (`SplitFamilyState`), :6287
**Copy-on-Split** [service] — the rule that a Split's children each deep-copy the parent cursor's whole scope — variables, counters, last output, branch markers, and the call stack — so sibling writes never reconverge. ↔ src/runtime.rs:5857
**Collector** [service] — the barrier node where parallel cursors join and branch results aggregate into a keyed `{inputs, summary}` JSON object in the representative cursor's scope. ↔ src/runtime.rs:5873 (`handle_collector_entry`), :6009. Decisions: ADR-260815-2009-05
**Collector Barrier** [entity] — the keyed join point where cursors arriving at a Collector wait until every merge key has arrived; it re-arms after release, so a loop can pass through one repeatedly. _Avoid_: join (the noun), rendezvous. ↔ src/runtime.rs:439 (`CollectorBarrierState`), :1959 (`reset_released_collector_barrier`)
**Barrier Key** [VO] — the `(scope, collector_id, execution_epoch)` triple identifying one Collector Barrier, where scope is `"root"` or the innermost call frame — so one collector reached from two concurrent subflow calls has two barriers. ↔ src/runtime.rs:267 (`CollectorBarrierKey`), :2049 (`collector_barrier_scope`)
**Merge Key** [VO] — the identity of one expected collector input: an inbound edge's `label`, falling back to its `from` node id; two inbound edges sharing a key are a validation error, so a runnable workflow never has them — the barrier builder's dedupe into a single required slot is reachable only when validation is bypassed. _Avoid_: describing the dedupe as the behaviour an author meets. ↔ src/runtime.rs:1930 (`merge_key_for_edge`), :1934 (`collector_required_inputs`), src/model.rs:2005 (the validation error)
**Representative Cursor** [entity] — the cursor that survives a Collector Barrier release and carries the run forward: the first still-live waiter in arrival order, whose variable scope wins while every other waiter is deleted and its writes discarded — or, when every waiter has died, a freshly minted cursor cloned from the barrier's snapshot of the first cursor to die into it. Release is gated on arrival count alone and never checks liveness, so under the default split failure policy the all-dead path is reachable. _Avoid_: surviving cursor, winner. ↔ src/runtime.rs:6041, :6046 (the fresh-cursor path), :6091, :6264 (`representative_snapshot`). Decisions: ADR-260815-2009-05 (constrains what it may carry)
**Parallel Batch** [entity] — the node that fans a bound list out over ephemeral cursors at a bounded concurrency, succeeding only if every item succeeded. ↔ src/runtime.rs:5081 (`handle_parallel_batch_node`), src/model.rs:463 (`BatchConfig`)
**Batch Item** [entity] — one element of a Parallel Batch's input list, executed by an ephemeral cursor that never enters the run's cursor list; results are keyed by index, so `collectorVar` is ordered by position, never by completion. ↔ src/runtime.rs:5509, :5295
**Call Frame** [entity] — the record pushed on a cursor's call stack at Subflow entry: a snapshot of the caller's variables, counters and branch markers, restored on exit, plus a separate `subflow_results` namespace the callee's node outputs are written to instead of the run's; the caller's last output is snapshotted too but never restored — exit overwrites it with the subflow's exit-node output, which is how a subflow returns a value. _Avoid_: stack frame. ↔ src/runtime.rs:178 (`CallFrameState`), :3532, :4691

### Agents, decisions, and panes

**Decide Node** [entity] — the node that asks an LLM to pick one of its declared Decide Outcomes and routes on the result, bypassing the task pipeline entirely — no orchestrator refinement, no retries, no session continuation, no agent defaults. ↔ src/runtime.rs:3785, src/model.rs:443 (`DecideConfig`)
**Decide Outcome** [VO] — one label in a Decide Node's declared `outcomes` list, matched exactly against a branch edge's `label`; an outcome with no matching branch edge is a validation error, so the runtime's emit-`workflow_error`-and-fall-through-to-success arm is unreachable from a validated document, and an outcome the model never names fails the node instead. _Avoid_: outcome (bare — that is Edge Outcome); describing the success fallthrough as behaviour an author can meet. ↔ src/model.rs:451, :2998, :3011 (the two validation errors), src/runtime.rs:4366 (`select_decide_outcome`), :6387, :6436 (the unreachable arm)
**Approval Queue** [entity] — the run's queue of pending approvals, activated strictly one at a time and re-bound on resume; a rejection with no `reject` edge ends its cursor as a failure, which outside a split family fails the whole run. ↔ src/runtime.rs:583 (`queued_approvals`), :3631 (`activate_next_approval`), :5065 (the no-reject-edge path)
**Pane Kind** [VO] — a Node Kind whose subject is a tmux pane rather than a prompt: `spawn` creates a pane and registers it in both the Active Pane Registry and the owned-target set; `send`, `wait`, and `capture` resolve a target by other means and then register it in the Active Pane Registry under their own node key; `kill` clears both. _Avoid_: pane node family, tmux node; describing `spawn` as the only kind that registers. ↔ src/tmux_exec.rs:292 (`run_tmux_node`), :559 (`ActivePaneRegistration`), :786 (spawn's two registrations), :814, :848, :890 (the send/wait/capture registrations), :957 (kill's clear)
**Active Pane Registry** [repository] — the per-run, in-memory map from pane key to tmux target consulted when a session-continuing node reuses a pane, and by the HTTP pane-context endpoints: a registered key, a raw target, the `active`/`current` aliases (only when exactly one pane is registered), or a bare node id matched against the trailing segment of the `cursor:node` key (`active_pane_key_matches_node` strips the node id as a **suffix**, not a prefix), highest sequence first. It does **not** resolve a Pane Kind's `target` — `send`/`wait`/`capture`/`kill` parse the target directly and gate it on the separate owned-target set. _Avoid_: pane registry as the pane-node lookup. ↔ src/runtime.rs:874, :1221 (`resolve_active_pane`), src/tmux_exec.rs:2454 (`resolve_pane_target`), src/runtime.rs:876 (`owned_tmux_targets`)
**Profile** [entity] _(planned — ADR-260815-2009-04)_ — a named, allow-listed bundle of agent + model + reasoning + tool config with a declared routing tier, from the app catalog (`profiles.json`) or the workflow-local `profiles` map (distinct from `agentDefaults`), selected per node via a `profile` field and per run by variable. _Avoid_: model string, preset, access profile (that is the separate, already-real concept).
**Access Profile** [VO] — the named argv bundle a `spawn` or `run_agent` node selects with `access`, validated against the names the Agents Registry declares for that agent — by the same validation pass as everything else, so advisory on request and enforced at run start, never on save — and applied outside the agent-defaults merge chain; distinct from `accessMode`, the four-variant `read_only | edit | execute | unrestricted` driver-level enum that defaults to `execute`. _Avoid_: access mode, profile (bare — that is the planned agent/model bundle). ↔ src/driver.rs:366 (`agent_access_profile_names`), src/model.rs:324, :2252 (`validate_agent_launch_config`)
**Agents Registry** [service] — the tmux-tools catalog of which agent CLIs are known and how to launch them: four compiled-in builtins (`agy`, `claude`, `codex`, `cursor`) deep-merged with an optional `~/.config/tmux-tools/agents.toml`. It records nothing about installation — whether a CLI is on PATH is a separate probe — and registry membership, not installation, is what decides the agent list `/api/capabilities` publishes. Profiles reference it, never replace it. _Avoid_: record of which CLIs are installed. ↔ src/driver.rs:224 (`load_agent_registry`), :1136 (`all_drivers`), src/runtime.rs:1678 (`check_cli`, the PATH probe)

### Testing

**Logic Tier** [VO] _(planned — ADR-260902-0312-01)_ — the majority tier of the test suite and the gate, whose rule is isolation of dependencies: a test drives its unit through that unit's own public contract, with every port replaced by a fake or supplied with controlled data. The unit's altitude varies and the rule does not — a single module or utility, or a use case reached at an API endpoint. Inside the boundary everything runs real; doubles appear only at ports. No spawned processes, no network, no shared mutable OS state, and no clock: never a sleep to sequence work, never an assertion about elapsed time, and never a wall-clock bound as the termination condition of a polling or convergence wait (the shape of the reproduced flake). A bound that fires only on a hang — wrapping an await a happens-before edge will end regardless — is permitted as a last resort, sized so expiry means a genuine hang and commented at the site. Stamping a record with the clock is permitted (it gates no control flow); deriving from it an identifier that enters state or event identity is not. Controlled data counts as isolation, so a temporary-directory database and a read-only committed file both belong here — which is what keeps the first-party invariant checks inside the gate. Membership in either tier is decided by what a test isolates, never by where its file lives; an out-of-crate member of either tier must additionally not depend on the `cfg!(test)` timeout shims, which do not apply across that crate boundary — a consequence of location, not of tier. _Avoid_: solitary test (the tier is a contract about what is isolated, not about a test's size or how many collaborators it runs against).
**Port** [VO] _(planned — ADR-260902-0312-01)_ — the interface at a unit's boundary through which it reaches something outside itself, and the only place a Logic Tier test is allowed to substitute anything. `NodeRunner` is the worked example: it is the seam in front of process execution, and the suite already carries eight alternative implementations of it. A collaborator inside the unit's boundary is not a port — code that cannot name the port it sits behind is internal, and a test reaches it through the enclosing interface instead. _Avoid_: seam (broader — every port is a seam, not every seam is a port); dependency. ↔ src/runtime.rs (`NodeRunner`), docs/adr/260902-0312-deterministic-test-tiers.md § "Doubles are fakes, and every fake names its port"
**Double** [VO] _(planned — ADR-260902-0312-01)_ — an alternative implementation of a Port: the same interface, a different mechanism, usually in-memory. In this repository a double is a **fake** — it holds real state a test reads back — and never a recorded expectation. Assert by reading state back through it, never that a call happened; interaction verification is a last resort for outgoing command-type calls with no observable state, and even then it asserts message content, never call counts or ordering. Every double names the port it is the second adapter for. _Avoid_: mock, stub, spy (all name expectation-recording shapes this repository does not use). ↔ docs/adr/260902-0312-deterministic-test-tiers.md § "Doubles are fakes, and every fake names its port"
**Integration Tier** [VO] _(planned — ADR-260902-0312-01)_ — the deliberately small tier that exercises chains of behavior end-to-end against real infrastructure: real SQLite round-trips against a migrated store, real subprocesses, real FIFOs, real tmux. What it isolates is the external world — dependencies that cost money, mutate data outside the test, or belong to someone else. Asserting on elapsed time is permitted only here, and only for a genuinely temporal property, with a generous bound. Excluded from the default command, which runs the Logic Tier alone, and added back by a single opt-in switch. Membership is decided by what a test isolates, not by location; the out-of-crate `cfg!(test)` shim constraint noted under Logic Tier applies to members of this tier too. Runs as the non-gating CI job, the gating job being the Logic Tier. _Avoid_: e2e tests (Playwright is a separate, third layer); slow tests.
**Performance Check** [VO] _(planned — ADR-260902-0312-01)_ — the third, non-gating category of the Rust suite, holding a test whose subject genuinely is elapsed time. It sits outside both correctness tiers because it is decided by what a test *asserts*, not by what it isolates: it fails the Logic Tier's clock rule, and its subject is not real infrastructure, so it is not Integration Tier either. Marked explicitly at the test, excluded from the default command, and added back by its own opt-in switch alongside the Integration Tier's. Where such a test also asserts a clock-free correctness property, that property is separated out and stays in the gate rather than leaving it as a passenger. _Avoid_: benchmark (the rejected alternative — it converts a failing assertion into a number a person has to read, deleting the guard); performance tier (it is not a tier, and the distinction is load-bearing: tier membership is decided by what a test isolates).
